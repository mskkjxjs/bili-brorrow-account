# 借用B站账号

一个用于 Chrome / Edge 的 Manifest V3 扩展：使用小号完成播放器的播放数据初始化和取流，直接以小号权限内的最高画质播放，同时让观看进度、观看历史、点赞、评论和消息继续使用浏览器当前登录的大号。

## 功能

- **账号分离**：仅番剧主文档、播放器初始化及播放地址请求使用小号 SESSDATA。
- **大号记录**：不接管观看历史或其他账号操作，无需提供大号 Cookie。
- **最高画质直出**：勾选“自动切换最高画质”后，扩展会丢弃页面内嵌的大号播放数据并改用小号重新取流，使播放数据到达播放器时已是小号可用的最高清晰度（例如 1080P60、4K、8K）；不勾选时使用 B 站默认画质。
- **扫码登录**：在扩展设置中直接扫码登录小号，成功后自动填入 SESSDATA、bili_jct 和 ac_time_value。
- **更新检查**：弹窗内手动检查更新，或开启每日自动检查；发现新版本时扩展图标显示角标并提示下载。
- **自动续期**：每日检查 Cookie 状态，需要时轮换 SESSDATA、bili_jct 和刷新令牌。
- **页面切换检测**：B 站站内跳转至其他视频后重新应用画质设置。
- **本地配置**：账号凭证和设置仅保存在扩展的 `chrome.storage.local` 中。

## 安装

1. 下载 [最新 Release](https://github.com/mskkjxjs/bili-brorrow-account/releases/latest) 中的 ZIP 文件并解压。
2. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
3. 开启“开发人员模式”。
4. 点击“加载解压缩的扩展”，选择解压后的目录。
5. 打开扩展设置，点击“扫码登录小号”或手动填写小号 SESSDATA，按需开启功能并保存。
6. 刷新已经打开的视频页面。

要求 Chrome 或 Edge 128 及更高版本。

## 使用方法

### 扫码登录小号

点击扩展设置中的 **扫码登录小号**，扩展会打开一个独立的小窗口展示二维码（避免弹窗失焦关闭导致扫码中断）。使用哔哩哔哩 App 扫描并在手机端确认后，扩展会把获取到的 **SESSDATA**、**bili_jct** 和 **ac_time_value** 自动填入三个输入框，点击“保存设置”即可。

扫码过程使用扩展自身的请求读取登录凭证，不会把浏览器的登录状态切换成小号，也不会修改浏览器保存的大号 Cookie。

### 小号初始化并取流

在扩展设置中填写 **SESSDATA 的值**（扫码可自动填入），不要包含 `SESSDATA=`、其他 Cookie 名称或分号，然后启用“小号初始化并取流”。

扩展仅向以下 B 站请求应用小号凭证：

- 普通视频及番剧的播放地址请求。
- 播放器 `v2` 初始化请求。
- 番剧主文档请求，用于让服务器生成小号的 SSR 播放数据。

启用“自动切换最高画质”后，普通视频页会跳过页面自带的大号播放数据，由播放器用小号重新请求取流地址；播放数据中的清晰度会被提升到小号在该视频上可用的最高项。未勾选时使用 B 站默认画质。实际可选画质仍取决于视频本身和小号权限。

番剧观看进度通过大号历史记录单独恢复。

请使用自己有权使用的账号。SESSDATA 等同于登录凭证，不要分享或提交到仓库。

### 自动切换最高画质

勾选“自动切换最高画质”（默认开启）后，扩展会在普通视频页跳过页面自带的大号播放数据，由播放器用小号重新请求取流地址，并把播放数据中的清晰度提升到小号在该视频上可用的最高项，同时自动选中画质菜单的第一项。小号有大会员权限时会直接播放 1080P60、4K、8K 等会员画质；小号没有权限时，会员档位仍会按 B 站规则提示开通。

不勾选时扩展不改动播放数据和画质选项，使用 B 站默认画质，也就不会因为自动选中会员档位而触发开通提示。该开关不需要重新填写凭证，保存后刷新页面即可生效。

### 自动续期 SESSDATA

自动续期需要同时填写 **SESSDATA**、**bili_jct** 和 **ac_time_value**。扫码登录会自动获得这三项；手动填写时，`ac_time_value` 可在对应账号浏览器的 `localStorage` 中获取，不是 Cookie，并且需要扫码登录时未选择一次性登录。

开启“每日检查并自动续期 SESSDATA”后，扩展会在浏览器启动、保存设置及每日定时任务中检查状态。仅在 B 站返回需要刷新时执行完整轮换，并保存响应中的新 SESSDATA、新 bili_jct 和新刷新令牌。

续期请求使用 `credentials: "omit"`，不读取浏览器 Cookie，也不让刷新响应写入浏览器 Cookie，因此不会覆盖大号登录状态。扩展仅通过 `webRequest` 读取自己发起的刷新响应。

### 检查更新

弹窗底部显示当前版本。点击 **检查更新** 会请求 GitHub Releases 接口并与当前版本对比：有新版本时显示最新版本号并给出“前往 GitHub 下载新版本”链接，否则显示“已是最新版本”。

勾选 **自动检查更新（每天一次）** 后，扩展会在浏览器启动和每日定时任务中静默检查；发现新版本时扩展图标显示橙色“新”角标，打开弹窗即可查看详情。自动检查只保存版本信息，不会自动下载或安装。

扩展以“加载已解压的扩展”方式安装，浏览器不允许扩展改写自身目录，因此更新需要手动下载 Release 中的 ZIP、覆盖扩展目录后重新加载。

## 隐私与权限

- `storage`：保存账号凭证和功能开关。
- `alarms`：每日检查是否需要续期。
- `webRequest`：仅读取扩展自己发起的扫码轮询和续期响应中的新 Cookie。
- `declarativeNetRequestWithHostAccess`：仅对指定番剧主文档、播放器及续期请求修改 Cookie 请求头。
- `www.bilibili.com`、`api.bilibili.com` 与 `passport.bilibili.com` 主机权限：识别视频页、处理播放器请求、扫码登录及完成凭证续期。
- `api.github.com` 主机权限：读取 Releases 接口的最新版本号，检查更新时不发送账号凭证。

扩展不会读取或修改浏览器保存的大号 Cookie，也不包含远程配置、分析统计或广告代码。

## 已知限制

- 自动续期依赖有效的 `ac_time_value`，无法恢复已经失效或未提供刷新令牌的登录状态。
- 同一个 `ac_time_value` 同时用于其它客户端（例如 blbl）时，任一方续期都会让另一方的刷新令牌失效。
- 勾选“自动切换最高画质”时，若小号没有大会员，自动选中的会员档位仍可能触发 B 站的开通提示；取消勾选可避免。

## 更新说明

### 1.3.0

- 新增“检查更新”按钮和“自动检查更新（每天一次）”选项，发现新版本时扩展图标显示橙色“新”角标，并提供 GitHub 发布页链接。

- 未打包扩展无法自我替换文件，更新仍需手动下载并重新加载扩展。

## 构建与发布

仓库通过 `.github/workflows/release.yml` 自动打包。推送与 `manifest.json` 版本一致的 `x.y.z` 标签后，GitHub Actions 会校验版本、生成扩展 ZIP 并创建 Release。
